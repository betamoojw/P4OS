# COM24 网页与诊断修复验证

后续 `1534227` 验证中发现的旋转触摸和校时问题，参见 [横竖屏触摸与网络校时修复](TOUCH-TIME-VALIDATION.md)。本文保留此前那次验证的结果。

日期：2026-10-23。基于 `dev` 的 `4cbf450` 工作区，开发板为 Waveshare ESP32-P4-WIFI6-Touch-LCD-10.1，COM24 读取为 ESP32-P4 v3.2。

## 修复内容

- 网页设置、固件页的异步响应和延迟刷新检查当前路由及导航序号，避免切换方向后覆盖已打开的页面；方向刷新等待设置请求完成。
- 固件 API 根据板型及最低硅版本返回构建路径。支持 5、7、8、10.1 英寸与 rev1_3、rev3_x 共八种组合，当前板提示 `build/lcd10_1/rev3_x/p4os.bin`。
- 应用列表按设备语言翻译；屏幕页长板型名称允许换行，不再挤压左侧标签。
- 修正网页和本机设置、固件、诊断页面中的音量、总线、固件分区、试运行、启动、重启原因、C6 说明及崩溃转储用语。繁体专用词句保存为可再生成的人工词表。
- I2C 仅在探测超时时延迟后重试一次，并记录端口、地址、SDA/SCL 电平及重试结果。正常 NACK 不重试，不重置触摸/音频共用总线。采样电平是故障发生后的读数，不能单凭它判定电气原因。

## 构建和自动测试

- 正式构建：`lcd10_1/rev3_x`，`AOS_I18N_SELFTEST=OFF`。应用 7,053,760 字节，应用分区剩余约 15%。
- 网页测试 21 项通过，包括请求延迟、方向切换后导航、离开再返回、两种中文和八种路径校验。
- 中文/网页资源/原生 UTF-8 共 8 项通过，简繁词表覆盖检查通过，新增文字均在已有 Flash 字库中。
- 板型合同 6 项通过，包含四种板型和两种硅版本的固件 API 路径预处理验证。本次完整固件只重新构建连接实机所用的 10.1 英寸 rev3_x，未宣称重新构建八种完整固件。
- I2C 故障注入测试 1 项通过，运行实际探测函数，覆盖成功、NACK、超时及重试后的三种结果组合；确认只有超时重试、最多两次探测、失败不会被报告为成功，低系统 tick 频率下仍至少等待一个 tick。

## C6 版本调查

P4 主端依赖为 ESP-Hosted 3.0.9，板载 C6 为 2.12.13。P4 的串口烧录不会更新 C6；该依赖的 MCU 迁移文档将 3.x 主端配合 2.x 协处理器列为向后兼容，并建议后续升级。当前无 microSD，而项目现有 C6 更新流程从卡上的 `/firmware/c6.bin` 读取；COM24 也不是 C6 的独立 J7 串口。本次没有升级 C6，没有隐藏版本诊断。操作说明补充在 `docs/C6.md`。

## 实机结果

- COM24 应用及 OTA 启动信息写入完成，两个区域的哈希校验通过。引导程序、分区布局及字库没有变更，本次保留原 Flash 字库和 NVS。构建字库 SHA-256 与源码资源一致，启动成功加载 20,501 个字形。
- 应用运行于 `ota_0`，ELF 前缀 `f7e506dd37b88ef2`；版本文字仍为基础提交 `v0.15.0-114-g4cbf450`，验证时工作区内的修复通过 ELF 标识及实际页面区分。串口与网页均确认设备 IP 为 `192.168.71.120`。
- 实机选择纵向后立即进入屏幕页，延迟刷新没有覆盖当前页；纵向镜像旁的开发板标签保持完整，长型号在右侧换行。
- `zh-Hans → zh-Hant → zh-Hans` 切换完成，串口确认语言应用，网页导航、应用选择器、本机界面同步。繁体更新页、诊断页的已查看文字无缺字；两种语言的固件页均显示正确构建路径。
- 繁体诊断页显示 C6 2.12.13、异常重启次数“無”、当机倾印“無”。没有把版本不一致标为已消除。
- 十分钟串口观察未出现 I2C 超时、panic、看门狗或非预期重启；后半段打开模块页持续自动探测 `i2c.ext`，并手动重新扫描。此前的偶发超时本次未复现，因此不能声称已确定电气根因或彻底消除故障。
- 实时镜像期间退出模块应用曾记录约 2 MiB PSRAM 未回收。停止镜像请求后 `/api/info` 显示可用 PSRAM 18,460,444 字节（约 18,028 KiB），恢复至打开模块前水平；与截图缓冲区的临时占用相符，未确认持续内存泄漏。
- 最后通过 COM24 再次重启，仍加载相同 ELF 和 Flash 字库、保留 `zh-Hans`，重新获取 `192.168.71.120`。结束时保持简体中文和横向；未更改本轮观察到的亮度 78、音量 85 及音效设置。

首次验证的 I2C 超时发生在探测路径；ESP-IDF 已在这种超时中复位事务状态机。本次保留其恢复机制，并补充有限重试及故障上下文。传感器自动探测排除 `i2c.board`，默认外部总线为 GPIO21/22 的 `i2c.ext`。启动时的上拉电阻警告仅由 `enable_internal_pullup=false` 触发，不能视为实际检测到外部电阻缺失。

没有进行 SD 文件上传、C6 升级或扬声器听音验证；这些不属于本次已通过的结果。
