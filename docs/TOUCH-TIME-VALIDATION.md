# 横竖屏触摸与网络校时修复

验证日期：2026-10-23。基于 `dev` 的 `1534227`。连接设备为 COM24 上的 Waveshare ESP32-P4-WIFI6-Touch-LCD-10.1，ESP32-P4 v3.2，构建配置为 `lcd10_1/rev3_x`。

## 原因与修复

### 旋转后的坐标越界

此前实机在横屏点击后切为竖屏，串口连续报告 `X is 803 which is greater than hor. res`。LVGL 会将上一次原始坐标作为下一次读取的初值；无触摸时 HAL 只更新释放状态，没有覆盖坐标。因此横屏下合法的 x=803 会在宽度为 800 的竖屏中一直残留。

- 在输入层同时约束按下、拖动和释放坐标，包括没有触摸时的缓存坐标。
- 切换方向时重置 LVGL 输入状态，取消待执行的远程输入及旧手势；实体手指未抬起前不向新布局发送按压，避免旋转导致误点击。
- 返回强制方向应用时，手势结束函数也可能触发旋转，因此返回 LVGL 前再次约束坐标。
- Goodix 原始点在旋转前按面板尺寸约束，所有手指及多指手势采样均使用相同边界。未改变四种屏幕的原有旋转映射。

### 网络校时

原固件只配置 `pool.ntp.org`。本次主机探测中，它解析出的一个地址超时，另一个地址可以回应；`ntp.aliyun.com` 和 `time.cloudflare.com` 也有可响应地址。这证明当前网络存在部分时间源不可达的情况，但不能仅凭主机结果还原上一轮开发板实际使用的地址。

原固件在上轮开机 286 秒时仍未校时；本轮烧录前，在开机 1062 秒时已经取得有效时间，因此不能描述为始终无法同步。本修复消除对单一域名/地址的依赖，并增加可验证的成功日志。

- 配置三个独立域名：`pool.ntp.org`、`ntp.aliyun.com`、`time.cloudflare.com`。由 ESP-IDF 自带的 lwIP SNTP 在 DNS/接收超时后切换，保留其退避及正常校时间隔。
- 仅在获得 Wi-Fi 地址后启动；重连重新启动校时。
- 手动校时请求通过系统事件队列串行处理，避免与获得 IP 的回调并发初始化。HAL 返回 true 只表示已排队，不表示校时完成。
- 启动失败会记录错误，初始化失败后允许再次初始化；实际接收到时间时单独记录 `SNTP synchronized: epoch=...`，不会将“发起请求”记为“同步成功”。
- 未同步时主页日期显示 `--`，避免把 1970 年的默认日期显示为有效日期。

公共服务配置参考：[阿里云公共 NTP 域名](https://help.aliyun.com/en/ecs/user-guide/alibaba-cloud-ntp-server/)、[Cloudflare NTP 使用说明](https://developers.cloudflare.com/time-services/ntp/usage/)。本修复使用原有 SNTP 协议，不通过浏览器或主机手动写入时间冒充网络校时。

## 构建配置

`sdkconfig.defaults` 设置 `CONFIG_LWIP_SNTP_MAX_SERVERS=3`，适用于所有板型及两种硅版本。已有构建目录的 `sdkconfig` 不会自动覆盖旧值；需将此项由 1 调整为 3 后重新配置并构建。编译检查会明确提示缺少这一设置，避免静默丢失备用服务器。

字库、分区布局、动态应用 ABI 和 NVS 格式均未改变，无需 SD 卡。

## 实机验证

- 正式构建成功，`AOS_I18N_SELFTEST=OFF`；应用 7,054,992 字节，分区剩余约 15%。版本 `v0.15.0-115-g1534227-dirty`，构建时间 `Oct 23 2026 22:46:10`，ELF SHA-256 `c40e776fc89736b8f79250c85e4e1297e315bd0df1f25976e9895f6a8c1444e9`。`dirty` 表示这份验证镜像是在提交修复前构建的，提交源码不会改变已烧录镜像的版本标识。
- COM24 写入引导程序、分区表、OTA 启动信息及应用，四处哈希校验通过。保留原字库和 NVS；本地字库 SHA-256 与源码资源一致，启动成功加载 20,501 字形。
- 首次记录的启动在 5.481 秒获得 IP 并请求校时，7.086 秒收到 SNTP 时间，即联网后约 1.6 秒。串口记录的 epoch 与主机接收时刻相差约 0.82 秒（含整数秒截断与串口读取延迟，不能作为授时精度测量）。网页与本机显示 UTC+8 的正确日期、时间。
- 横屏右侧点击后切为 800×1280 竖屏，保持竖屏观察；竖屏底部点击打开本机设置后切回 1280×800 横屏，两种方向的点击、列表拖动、打开应用和返回主页均可用。
- 简体、繁体均检查了横竖屏画面；本机繁体日期与语言页面、门户的应用名和导航正常显示。通过网页切换为繁体，再从本机语言设置切回简体，网页自动跟随。
- 从设置页选择竖屏并立即进入屏幕页，延迟刷新没有覆盖当前导航。

- 最终通过 COM24 再次重启，相同 ELF、简体中文、横屏 1280×800 均保持。5.612 秒获得 IP，9.642 秒收到新的 SNTP 时间，即联网后约 4.0 秒；与主机接收时刻相差约 0.96 秒。两次成功日志均来自网络校时回调，未手动设置时间。
- 第一轮约 7 分钟操作记录和最终 90 秒重启记录中，坐标越界、I2C 超时、panic、看门狗均为 0。已有的 P4 主端 3.0.9 / C6 2.12.13 版本提示仍保留，本轮未改动 C6。
- 结束时为简体中文、横屏、UTC+8；亮度 78、音量 85 保持不变。只验证已查看页面的字形和布局，不据此宣称逐页检查所有动态应用；本轮未进行 SD 文件上传。

实机触摸验证通过管理网页注入点击/拖动，并运行开发板实际输入与绘制代码；实体手指跨旋转的抬手行为由生产 C 函数回归测试覆盖，未额外取得现场手指操作确认。网络超时切换采用 SDK 的现成实现，本轮没有在实机上人为阻断指定 NTP 服务器。
